# 聊天记录导入指南

记忆桌宠需要你和 TA 的聊天记录，才能学会 TA 说话的方式。本页说明怎样把聊天记录导出成文件，再交给桌宠导入。

所有处理都在你自己的电脑上完成，聊天记录不会上传。

## 导入之前，请先读这几条

- **只导入你有权处理的聊天记录**：你自己账号里、你参与过的对话。不要导入别人手机或电脑里的记录。
- **对方还在世的话，建议先征得 TA 的同意**。用一个人的说话方式生成对话，是件需要尊重对方的事。
- **导出的文件里是明文聊天记录**，可能包含手机号、地址、照片等隐私。导入完成后请妥善保管或删除导出文件，不要发到群里或网盘。
- 桌宠导入时默认会把手机号、身份证号、银行卡号、邮箱、详细地址、密码 / 验证码替换成「[手机号]」这样的标记，红包、转账、系统提示、撤回提示和链接卡片会被过滤掉，图片、表情、语音只保留「发过一张图片」这样的占位。脱敏是自动规则，不能保证 100% 识别，导入后可以在预览里再检查一遍。
- 群聊记录里，除了你和 TA 以外的成员会被改成「群友A」「群友B」，也可以选择直接去掉他们的发言。

## 支持哪些文件

| 来源                        | 文件                                            |
| --------------------------- | ----------------------------------------------- |
| chatlog-keeper（微信）      | `wechat_messages.json`                          |
| chatlog-keeper（QQ / NTQQ） | `qq_messages.json`                              |
| WeChatExporter              | `chat.json`（推荐）、`chat.txt`、`chat.csv`     |
| wx-cli                      | 导出的 `.json`、`.txt`、`.md`                   |
| 旧版 QQ 消息管理器          | `.txt`、`.mht`                                  |
| 表格（Excel 另存为 CSV）    | 列名为 时间 / 发送者 / 内容 的 `.csv`           |
| 自己整理的 JSON             | `[{"time": …, "sender": …, "text": …}]`         |
| 备份导出的 JSON             | `CreateTime`、`talker`、`msg`，或 `content.msg` |
| 分行 TXT                    | 一行时间、一行发送者、下面是正文                |
| 直接存成文件的文字          | 见下方「纯文本格式」                            |

聊天截图（png、jpg、webp）可以拖进角色管理的截图区。文字在这台电脑上读取，不上传，也不调用云端识别。保存之前会列出抽出的句子，并标明是你、对方，还是分不出来。可以删掉一句、一张图，或全部不保存。读不出文字的图片不会用来保存角色。这不是上表里的导出文件，也不会读取微信数据库。

导入后，桌宠会列出记录里出现的所有发送者，请你选出哪个是「我」、哪个是「TA」。

## 微信

微信的聊天记录保存在电脑上的加密数据库里，需要先用第三方导出工具导出。下面三个工具都是开源项目，**步骤以各工具官方 README 的最新说明为准**，工具更新后命令和界面可能变化。

使用前请注意：

- 这些工具需要电脑版微信**已登录**，并且聊天记录已经同步到电脑（手机上的记录可以先用微信自带的「聊天记录迁移与备份」迁移到电脑）。
- 它们获取数据库密钥的方式各不相同，部分方式需要关闭 macOS 的系统完整性保护（SIP）或以管理员身份运行，可能有账号风险。请先阅读各工具的风险说明，自行判断是否使用。
- 只导出你需要的那一个联系人即可，不必导出全部聊天。

### chatlog-keeper（Windows / macOS / Linux，命令行）

项目地址：<https://github.com/labazhou2024/chatlog-keeper>

1. 按 README 安装（需要 Python 3.9+），或在 [Releases](https://github.com/labazhou2024/chatlog-keeper/releases) 下载对应系统的单文件程序，并按 README 校验 `.sha256`。
2. 保持微信登录，先运行 `probe` 查看能否导出：
   ```bash
   python -m chatlog_keeper.cli probe
   ```
3. 导出微信记录（`--days` 是导出最近多少天，想要更早的记录就把天数调大）：
   ```bash
   python -m chatlog_keeper.cli wechat --days 365 --out ./out
   ```
4. 得到 `out/wechat_messages.json`，把它导入桌宠。这个文件里包含所有会话，导入时请在列表中选择和 TA 的那一个（默认选消息最多的会话）。

README 里有关于获取密钥方式与封号风险的说明表，请务必先看。

### WeChatExporter（macOS / Windows，图形界面）

项目地址：<https://github.com/93857536-pixel/WeChatExporter>

1. 在 [Releases](https://github.com/93857536-pixel/WeChatExporter/releases/latest) 下载：macOS 用 `WeChatExporter-macOS-universal.dmg`，Windows 用 `WeChatExporter-Windows-x64.zip`。
2. macOS 首次捕获密钥需要关闭 SIP；Windows 建议首次「以管理员身份运行」。详见 README 的「系统要求」。
3. 打开应用，点击「准备数据」→ 选择和 TA 的会话 →「导出选中」。
4. 导出结果默认在「下载 / 微信聊天记录导出」文件夹，把其中的 `chat.json` 导入桌宠（`chat.txt` 也可以）。

### wx-cli（命令行）

wx-cli 最初的仓库（jackwener/wx-cli）目前已无法访问。社区维护的版本有：

- [pandorafuture/wx-cli](https://github.com/pandorafuture/wx-cli)（macOS Apple Silicon，微信 4.1.7 及以上）。按 README 完成 `wx-cli doctor`、`wx-cli key extract`（需要关闭 SIP）、`wx-cli decrypt` 后，导出和 TA 的会话：
  ```bash
  wx-cli export 小鹿 -o ./export --all --format json
  ```
  得到 `小鹿_日期.json`，导入桌宠即可（`--format txt` 导出的文本也支持）。
- [jackwener/wx-cli-again](https://github.com/jackwener/wx-cli-again)（原作者的新版本）。按 README 完成 `wx init` 后：
  ```bash
  wx export "小鹿" -n 50000 --format markdown -o chat.md
  ```
  `--format json` / `--format txt` 导出的文件同样支持。注意 `-n` 是导出条数上限，默认值较小，想导出完整记录请调大。

WeChatExporter 在 Mac 上内置了 wx-cli，用它导出的 `chat.json` 也是这种格式，直接导入即可。

### 为什么桌宠不直接读取微信

微信的本地数据库是加密的，读取它需要从正在运行的微信里提取密钥。这类操作依赖微信的具体版本，经常随微信更新失效，有的方式还需要关闭系统安全保护，存在账号风险和法律上的不确定性。记忆桌宠因此**不内置任何微信 / QQ 解密功能**，只读取你用导出工具导出的文件：由你决定导出什么、导出多少，桌宠只接触你交给它的那一个文件。

## QQ

- **新版 QQ（NTQQ）**：用 chatlog-keeper 导出，运行 `python -m chatlog_keeper.cli qq --days 365 --out ./out`，得到 `out/qq_messages.json`。同样需要 QQ 已登录，详见上面 chatlog-keeper 的说明。
- **旧版 QQ（QQ 9 及更早的 PC 版）**：打开「消息管理器」，在左侧选中和 TA 的会话，右键「导出消息记录」，保存类型选「文本文件（_.txt）」或「网页格式（_.mht）」。txt 只有文字；mht 会带上图片，但桌宠只读取文字部分。不同 QQ 版本菜单位置可能不同，以你使用的版本为准。

## 表格 / 自己整理的记录

**CSV**：第一行是列名，至少要有时间、发送者、内容三列，中英文列名都可以识别（如 `时间,发送者,内容` 或 `time,sender,content`）。时间可以写成 `2024-01-02 21:03:05`，也可以是 Unix 时间戳。

```csv
时间,发送者,内容
2024-01-02 21:03:05,小鹿,哲哲在干嘛～
2024-01-02 21:03:40,阿哲,刚下班
```

**JSON**：

```json
[
  { "time": "2024-01-02 21:03:05", "sender": "小鹿", "text": "哲哲在干嘛～" },
  { "time": "2024-01-02 21:03:40", "sender": "阿哲", "text": "刚下班" }
]
```

## 纯文本格式

把聊天记录存成 TXT 再选择该文件。每条消息以「时间 + 发送者」开头，下面这些写法都能识别（同一份记录请用同一种写法）：

```text
2024-01-02 21:03 小鹿: 哲哲在干嘛～
2024-01-02 21:04 阿哲: 刚下班
```

```text
[2024/1/2 21:03:05] 小鹿：哲哲在干嘛～
[2024/1/2 21:04:10] 阿哲：刚下班
```

```text
2024-01-02

小鹿 21:03
哲哲在干嘛～

阿哲 21:04
刚下班
```

```text
小鹿 2024/1/2 21:03:05
哲哲在干嘛～
```

```text
2024-01-02 21:03:05
小鹿
在吗
真的

2024-01-02 21:03:40
阿哲: 刚下班
```

备份工具导出的 JSON 也可以，字段用 `CreateTime`、`talker`、`msg`。正文若包在对象里，读 `content.msg`。这仍然是导出文件，不是微信数据库，应用不会解密 `.db`。

- 一条消息有多行时，后面的行会自动接到上一条消息里。
- 日期也可以写成 `2024年1月2日 下午9:03`。
- 只写了时间、没有日期时也能导入，但只能按先后顺序推算日期。
- 图片、表情可以写成 `[图片]`、`[表情]`，桌宠会把它们当作「发了一张图片」。
- 时间按北京时间（UTC+8）理解。

## 导入失败怎么办

- 提示「无法识别这个文件的聊天记录格式」：确认文件是上面列出的某种导出文件，没有被改过格式；纯文本请对照上面的示例检查时间和发送者的写法。
- 提示「这是加密的数据库文件」：你选的是微信 / QQ 的原始数据库（如 `.db`），请先用导出工具导出。
- 发送者列表里出现了奇怪的名字（如 wxid 开头的一串字母）：这是导出工具没有解析出昵称，选择时把它当作对应的人即可。
